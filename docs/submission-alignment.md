# Submission Alignment

This document maps FitStyle Map to judge-review expectations.

## Requirement Checklist

| Requirement | Coverage |
|---|---|
| Working project | Next.js app with interactive UI and local API route |
| Category | Consumer lifestyle / shopping decision support |
| Project description | README explains the problem, product concept, and review flow |
| Demo video | UI and architecture support a short product walkthrough |
| Code repository | Public code includes typed contracts and decision logic |
| Setup instructions | README includes install and run commands |
| Sample data | Public sample cases are included in `lib/publicSampleCases.ts` |
| Running guidance | README includes a step-by-step review flow |
| Codex / GPT-5.6 usage | Codex and GPT-5.6 helped build the MVP flow, architecture docs, release scoping, and review-ready code surface |

## Suggested Demo Video Outline

Keep the video under three minutes:

1. Problem: VTO is expensive and weak when every outfit is generated before fit
   screening.
2. Product: FitStyle Map adds a pre-VTO decision layer.
3. Workflow: select a model, compare outfit candidates, inspect PASS / REVIEW /
   HOLD reasons, then send the right looks to visual proof.
4. Engineering: show the public repo, decision engine, typed API contract, and
   architecture diagram.
5. Codex and GPT-5.6: explain how they accelerated UI iteration, release
   cleanup, architecture scoping, and final submission packaging.

## Submission Assets

- Hosted app URL: live FitStyle Map staging URL.
- Code repository URL: this public repository.
- Demo video URL: public or unlisted video link.
- Project description: use the README concept summary.
- Testing notes: include any judge access instructions separately.

## Official Reference Points

- OpenAI Build Week describes judging around technical implementation, design and
  user experience, potential impact, and idea quality.
- Devpost submission guidance asks for a working project, category, project
  description, demo video, code repository, setup instructions, sample data if
  needed, running guidance, and a clear explanation of how Codex and GPT-5.6
  were used.
